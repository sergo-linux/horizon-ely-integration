# Проверка совместимости и статус

Дата исследования: 30 октября 2026.

После публикации исходного пакета CI подтвердил применение/откат на upstream
и тесты Python на трёх ОС для коммита `280ef8e`. Это не проверка нативной сборки.
Добавленный позднее `installed.py` имеет отдельные тесты с неисполняемыми
фиктивными заголовками PE/ELF/Mach-O; он не запускался на настоящей установке.
Проверка скопированных ресурсов ограничена структурой каталога 26.3, поэтому
реальная совместимость ресурсов не заявляется и нужен `--experimental`.

Подтверждено чтением фиксированных исходников:

- Базовая ревизия и изменения Elyhorizon указаны в compatibility.json.
- Ely.by — отдельный provider, токены идут в штатную OS keychain через
  существующий SecretStore. При отсутствии keychain — память процесса.
- Сессия с `user_type: ely` направляет join на Ely.by.
- Локальный профиль возвращает пустую сессию и не имеет download entitlement.
- Скины разрешаются по Ely.by профилю в фоновом Resolver; classic/slim извлекается
  из textures. Новый транспорт обновляет HTTP-адреса Ely.by до HTTPS, запрещает
  перенаправления и ограничивает размер сетевого ответа.
- Самообновление лаунчера в этой сборке отключено; клиент берётся рядом с ним.
- Данные и keychain service отделены от основного Horizon.

Локально выполнены только статические проверки: синтаксис Python/Bash,
разбор изменённых Rust-файлов, SHA-256 payload и применимость unified diff
к сохранённым исходным файлам (`git apply --check`). Эти проверки не доказывают
корректность Rust-типов, линковки, сетевого протокола или рендеринга.

Не выполнялись: применение пакета к установленному лаунчеру, запуск патчера,
запуск игры, установка зависимостей, нативная компиляция, запуск созданных тестов,
вход с реальным Ely.by аккаунтом и публикация на GitHub.

Перед выпуском требуется:

1. Запустить `python -m unittest discover -s tests -v` на Windows/Linux/macOS.
   Тесты используют временные файлы и подмену Git, проверяют отказ при изменённых
   исходниках/бэкапах, частичную запись, откат, пути и адреса текстур.
2. Выполнить workflow `Check patch package` на настоящем checkout upstream.
3. Выполнить ручной `Experimental native builds`: он компилирует оба компонента
   и запускает unit-тесты аккаунтов и нового модуля текстур. Сам workflow пока
   не выполнялся; зелёной матрицы ОС нет.
4. Проверить собственный device-code client ID с Ely.by. Проверить вход, отмену,
   истечение кода, обновление и отзыв токена, отсутствие ключницы.
5. Пройти подготовку ресурсов для фиксированной базы, GUI и CLI Play.
6. Проверить свой скин classic/slim в первом/третьем лице, скин другого игрока,
   отсутствие скина, смену скина и повторный запуск без сети.
7. Проверить отказ Microsoft-сервера для Ely.by аккаунта и успешный вход
   на тестовый сервер с Ely.by. Rust-сервер не заявляется совместимым.
8. Проверить права на приватный session file на Windows; базовый код гарантирует
   Unix mode 0600, но дополнительного Windows ACL-аудита здесь не проводилось.
9. Провести нагрузочные проверки исходного Downloader: он использует фоновые
   потоки и исходные PNG-декодеры. Новая часть ограничивает размер ответа,
   но не является полноценной защитой от всех вредоносных текстур сервера.

Публичный HTTPS-запрос метаданных `skinsystem.ely.by/textures/ErickSkrauch`
при исследовании вернул JSON с адресом скина. Это подтверждает только доступность
этого endpoint в момент запроса. Device code, загрузка PNG и рендеринг этим
запросом не проверяются. Другой запрос публичного профиля завершился тайм-аутом.
