# Horizon Ely.by — экспериментальный патчер исходников

Постоянные локальные профили, вход Ely.by и маршрутизация скинов для отдельной
сборки Horizon. Python 3.10+, Git; оболочки Bash и PowerShell 5.1+.

**Статус: экспериментальные исходники. Нативная сборка, реальный вход Ely.by,
рендеринг скинов и запуск на Windows/macOS/Linux здесь не проверены.**
Нельзя публиковать пакет под видом проверенного активатора готового `.exe`.

Для компьютера с уже установленным Horizon подготовлен отдельный путь без
локальной компиляции: [INSTALLED.md](INSTALLED.md). Он требует готового
нативного артефакта этого пакета и устанавливает отдельную сборку рядом,
копируя подготовленные ресурсы. Официальные бинарные файлы не переписываются.

## Что включено

- GUI/CLI/MCP входа Ely.by, OAuth device code, обновление токена и выход —
  адаптация существующей MIT-интеграции Elyhorizon с указанием авторства.
- В этой сборке локальный профиль доступен без переменных окружения и аккаунта.
  Проверки и сессии выбранных Microsoft/Ely.by аккаунтов сохраняются; локальный
  профиль не выдаётся за подтверждённую лицензию.
- Скины Ely.by для выбранного Ely.by аккаунта: собственный профиль по UUID,
  модели classic/slim, допустимые адреса текстур, фоновые запросы и дисковый кэш.
  Свой профиль запрашивается через Ely.by; свойства других игроков из сервера
  принимают адреса Ely.by только в сеансе Ely.by. Автоматический поиск скина
  каждого неизвестного игрока по имени не реализован.
- Экспорт публичного скина и доступного плаща в PNG командой `skin`.
  Экспорт не доказывает владение аккаунтом и не выполняет вход.
- Публичные профили кэшируются для работы при сбое сети. Если профиль или
  изображение никогда не загружались, офлайн-копии нет. Загрузка в фоне использует
  существующий механизм Horizon; обновление своего скина — при следующем запуске.
- Отдельные каталоги данных и отдельный service name ключницы.
- Самообновление лаунчера отключено в коде. Автоустановка игры по умолчанию
  выключена. Самостоятельное обновление пакета требует новой проверки совместимости.
- Лаунчер всегда запускает сопутствующий `horizon-client` из своего каталога.
  При отсутствии файла обычный официальный клиент не подставляется.
- Проверка SHA-256 исходников, полные резервные копии, журнал операции,
  восстановление после прерывания, отказ от отката поверх последующих изменений.

## Границы совместимости

Единственная база: `horizon-rust/horizon@56f968e11c7627536cb6a83420caddce7e3acb8f`.
Сторонняя интеграция: `Tsifrokayf/Elyhorizon@333ca09d09476766ae3ffbf98bf41583df9f8b7d`.
Это ревизия исходников, а не обещание совместимости со всеми Horizon 0.2.x.
Форку уже недостаёт изменений современного upstream; перенос на другую базу —
отдельная работа с повторной проверкой и сборкой.

Патчер переносим между ОС. Нативные бинарные файлы собираются отдельно для
каждой ОС и архитектуры. CI подготовлен для Windows x64, Linux x64 и macOS
Apple Silicon. Intel Mac, ARM Linux и Windows ARM не подтверждены.

Плащи можно скачать/экспортировать. Их визуальное отображение в клиенте не
заявляется: загрузка текстуры и её отрисовка — разные части игры.
Также не заявляются HD-скины, уши, редактирование/загрузка скина на Ely.by,
отображение скина другим игрокам без поддержки Ely.by на их стороне и
полная криптографическая проверка подписей текстур. Проверка поля `signature`
унаследована от базового клиента; пакет не добавляет проверку подписи RSA.

## Применение к копии исходников

Все команды ниже выполняет пользователь самостоятельно. Пакет ничего
не устанавливает, не подменяет установленный Horizon и не собирает код автоматически.
Не применяйте его поверх предыдущего `patch-horizon-offline.ps1`.

```bash
git clone -c core.autocrlf=false https://github.com/horizon-rust/horizon.git horizon-local
git -C horizon-local checkout --detach 56f968e11c7627536cb6a83420caddce7e3acb8f
python3 horizon_ely.py check --source horizon-local
python3 horizon_ely.py apply --source horizon-local
python3 horizon_ely.py status --source horizon-local
```

PowerShell: используйте `py -3` вместо `python3`, либо оболочку:

Параметр `-c core.autocrlf=false` в команде `clone` сохраняет исходные LF
в этой копии репозитория. Это необходимо для точной проверки SHA-256 на Windows.

```powershell
.\patch.ps1 check --source C:\src\horizon-local
.\patch.ps1 apply --source C:\src\horizon-local
.\patch.ps1 rollback --source C:\src\horizon-local
```

Bash-оболочка: `bash patch.sh apply --source /путь/horizon-local`.
`horizon-ely.patch` — альтернативный unified diff для ручного ревью, а не
дополнительный шаг после `apply`. Для управляемых резервных копий используйте Python CLI.

## Регистрация приложения Ely.by

Для настоящего входа издателю нужен собственный публичный клиент Ely.by с
поддержкой device authorization. Его публичный client ID встраивается при сборке
через `HORIZON_ELY_CLIENT_ID`. Пароли пользователей скрипту не нужны.
Не помещайте `client_secret`, refresh token или чужой client ID в исходники.

**Ограничение:** публичная документация Ely.by описывает обычный OAuth code flow,
а заимствованный форк использует device-code endpoints по образцу ElyPrism.
Доступность этого режима для нового приложения не подтверждена. Перед выпуском
согласуйте тип приложения с Ely.by и проверьте вход своей регистрацией.
Если выдан только confidential client с секретом, его нельзя встраивать
в публичную настольную сборку; потребуется другой поток авторизации.

В GitHub Settings → Secrets and variables → Actions → Variables добавьте
`HORIZON_ELY_CLIENT_ID`. Это публичный идентификатор приложения.
После этого ручной workflow `Experimental native builds` сможет встроить ID.
Без ID workflow собирает только локальные профили, без входа Ely.by.

## Самостоятельная сборка

Нужны Rust и системные зависимости Horizon/GPUI. Полный их установщик в пакет
не входит. Команды выполняются из корня изменённой копии Horizon:

```bash
export HORIZON_ELY_CLIENT_ID='ВАШ_ПУБЛИЧНЫЙ_CLIENT_ID'
export HORIZON_LAUNCHER_VERSION='0.0.0-ely-experimental'
cargo test --locked --manifest-path launcher/Cargo.toml --lib account::tests
cargo test --locked -p horizon-client --lib skins::ely_skins
cargo build --locked --release --manifest-path launcher/Cargo.toml
cargo build --locked --release -p horizon-client --bin horizon-client
```

PowerShell задаёт значения через `$env:HORIZON_ELY_CLIENT_ID = '...'` и
`$env:HORIZON_LAUNCHER_VERSION = '0.0.0-ely-experimental'`.
На macOS без Metal toolchain лаунчеру может потребоваться
`--features gpui/runtime_shaders`.
Кодовые Wasm-моды не входят в стандартную сборку клиента; для них нужен
дополнительный feature `mods` и отдельная проверка.

Из каталога пакета соберите два готовых файла в новый каталог:

```bash
python3 horizon_ely.py bundle --source /путь/horizon-local --out ./dist/native
```

`bundle` не компилирует код. Он проверяет исходники и маркеры интеграции,
затем копирует уже собранные лаунчер и клиент рядом. При `CARGO_TARGET_DIR`
в нестандартном каталоге поиск результатов не поддерживается; используйте
стандартные target-каталоги. Для явного Cargo target передайте `--target`.
Бинарные артефакты macOS не подписаны и не нотарифицированы; полноценный `.app`
и установщики этим пакетом не создаются.

## Аккаунт и запуск

Для входа: `horizon-launcher account sign-in --ely`.
Далее `account list`, `account select ИМЯ` и `account sign-out ИМЯ`.
Для локального имени: `horizon-launcher account offline Friend_1`.
Эти команды относятся к новой сборке, не к установленному официальному лаунчеру.

Нужны подготовленные ресурсы Minecraft/Horizon, совместимые с этой базой.
Пакет не включает их и не выдаёт Ely.by за Microsoft-лицензию для скачивания
из Mojang. Нельзя считать ресурсы произвольной новой Nightly совместимыми
со старым сопутствующим клиентом. Проверка полного цикла подготовки ресурсов
остаётся обязательной перед публичным релизом.

Клиент Ely.by может войти на сервер, настроенный на Ely.by. Сервера, проверяющие
Microsoft/Mojang, такой аккаунт не принимают. Серверная сторона Rust Horizon
в этом пакете не переведена на Ely.by `hasJoined`.

## Экспорт скина и плаща

```bash
python3 horizon_ely.py skin --name Player_1 --out ./textures-player-1
```

Если сервис отдаёт текстуры, новый каталог получит `skin.png`, доступный
`cape.png` и `textures.json` с моделью. Существующий каталог не перезаписывается.
Экспорт не устанавливает скин в профиль автоматически и не создаёт аккаунт.
Для локального профиля скин можно назначить штатной командой вашей сборки:

```text
horizon-launcher account skin Friend_1 /полный/путь/skin.png --model slim
```

Модель берите из `textures.json`. Поддержка изображения в конкретном рендерере
всё равно требует проверки; команда назначения не является такой проверкой.

## Данные и откат

По умолчанию данные лаунчера лежат в `horizon-ely-launcher`, игры — в
`horizon-ely` внутри системного data directory. Для Linux это обычно
`~/.local/share`, macOS — `~/Library/Application Support`, Windows — `%APPDATA%`.
Уважаются `HORIZON_LAUNCHER_HOME` и `HORIZON_HOME`; задавая их на каталоги
основного Horizon, вы сами отключаете разделение файлов.
Ключница использует service `dev.horizon.elyintegration.launcher`.
Аккаунты обычного Horizon автоматически не импортируются.

Резервные копии исходников находятся в `.horizon-ely-patch` внутри переданной
копии репозитория. Они не содержат пользовательских токенов или конфигураций.

```bash
python3 horizon_ely.py rollback --source /путь/horizon-local
```

Откат возвращает исходные байты, удаляет добавленные исходники и переносит
копии в `.horizon-ely-patch-restored`. Более поздние ручные изменения блокируют
откат. Откат исходников не изменяет собранные программы, аккаунты, кэш или миры.
Чтобы отменить поведение своей сборки, прекратите её использовать или
пересоберите восстановленный код. Для новой операции сохранённый архив
предыдущего отката нужно переместить вручную в другое место.
